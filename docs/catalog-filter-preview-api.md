# Предпросмотр результата фильтрации

Плашка «Найдено товаров / Показать» использует отдельный лёгкий запрос и не
загружает карточки товаров. Запрос отправляется после изменения чекбокса,
радиокнопки, скидки или цены и содержит всё текущее состояние фильтров.

## Настройка фронтенда

```html
<script>
  window.VinResultsConfig = {
    api: "fetch",
    endpoints: {
      filterPreview: "/api/catalog/filter-preview",
    },
    context: {
      selectionType: "vin",
      vin: "Y6DTF69Y080144158",
    },
  };
</script>
```

В локальной статической странице используется `api: "mock"`. Плашка временно
отключена непосредственно в моковых данных:

```js
mockData: {
  filterPreview: {
    enabled: false,
    total: 106,
    resultsUrl: "#catalog-products",
  },
}
```

При `enabled: false` mock не запускает показ плашки. На интеграции с бэкендом
используется режим `fetch`, поэтому моковый выключатель на него не влияет.

## POST `/api/catalog/filter-preview`

Заголовок запроса: `Content-Type: application/json`.

```json
{
  "filters": {
    "groups": ["brakes", "clutch"],
    "teeth": "02",
    "power": "05",
    "discount": true,
    "price": {
      "min": 2000,
      "max": 5000
    },
    "vehicle": {
      "brand": "bmw",
      "model": "x5",
      "year": "2022"
    }
  },
  "changedFilter": {
    "id": "groups",
    "value": "brakes",
    "selected": true
  },
  "context": {
    "selectionType": "vin",
    "vin": "Y6DTF69Y080144158"
  }
}
```

- `filters` — полный набор активных фильтров. Неактивные поля не передаются.
- Мультивыбор передаётся массивом, одиночный выбор — строкой.
- `discount` передаётся только во включённом состоянии.
- `price` передаётся только если пользователь изменил исходный диапазон.
- `vehicle` передаёт каскадный выбор автомобиля на странице категории. Поля
  появляются последовательно (`brand` → `model` → `year` → `modification`) и
  отсутствуют, пока значение не выбрано. Сброс фильтров удаляет весь объект.
- `changedFilter` нужен для диагностики и аналитики; расчёт результата всегда
  должен опираться на полный объект `filters`.
- При изменении цены `changedFilter.value` содержит объект `{ "min", "max" }`.
- `context` идентифицирует исходный сценарий подбора. Бэкенд может расширить его
  серверными данными сессии, но не должен доверять VIN из браузера как
  авторизационному признаку.

Успешный ответ:

```json
{
  "total": 765,
  "resultsUrl": "/catalog/?groups=brakes&groups=clutch&teeth=02&power=05&discount=1&priceMin=2000&priceMax=5000"
}
```

- `total` — обязательное неотрицательное число найденных товаров.
- `resultsUrl` — относительный URL применения фильтров. Если поле отсутствует,
  фронтенд использует `#catalog-products` на текущей странице.
- В целях безопасности фронтенд принимает только относительный или same-origin
  URL. Внешний URL будет заменён на `#catalog-products`.

Ошибки возвращаются обычными HTTP-статусами (`4xx`/`5xx`). При ошибке плашка
скрывается, а уже выбранные фильтры остаются без изменений. Предыдущий запрос
отменяется через `AbortController`, поэтому устаревший ответ не перезаписывает
результат более нового изменения.
